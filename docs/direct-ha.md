# Прямые команды Home Assistant без LLM

Эта ветка основана на upstream **v0.7.6**. Добавлен режим `local`: только
явно заданные фразы вызывают сервисы Home Assistant напрямую по локальному
HTTP API. ChatGPT, другая нейросеть и MCP для этого режима не используются.
Все остальные фразы, включая музыку, обрабатывает штатная Алиса.

Распознавание речи остаётся у Яндекса и требует интернета. Успешное выполнение
HTTP-запроса подтверждается коротким штатным звуком `AliceIoTSoundsDone`, без
синтеза речи. Ошибки HA озвучиваются; после ошибки команда не повторяется в
Яндексе. Принятие запроса HA не гарантирует физического изменения устройства.

Проверено на рутованной **Mini 1 YNDX-0004**, ARM64, прошивка `1.374.4.23`.
Подтверждена работа голосовой команды через HA. Музыкальный запрос прошёл
штатный облачный маршрут и получил audio_play; акустическая проверка музыки
пользователем отдельно не зафиксирована.

## Фразы

Пример без секретов: [`config.local.example.json`](../config.local.example.json).

| Фразы | HA entity_id |
|---|---|
| включи свет / выключи свет | `switch.cabinet` |
| включи вентиляцию / выключи вентиляцию | `switch.ventiliatsiia` |
| включи ночник / выключи ночник | `switch.nochnik` |

Список редактируется в `direct_ha.rules`; имя сервиса и сущности задаются явно.
Поддерживаются `turn_on`/`turn_off` для `switch`, `light`, `fan`, `input_boolean`.
Адрес HA должен содержать частный или loopback IP. Редиректы и HTTP-прокси
отключены, время запроса ограничено восемью секундами, автоматических повторов нет.

Совпадение точное после нормализации регистра, пробелов, ё/е, обращения «Алиса»
и конечной пунктуации. Например, «включи свет в детской», «не включи свет» и
«включи свет и вентиляцию» не совпадут и останутся у Яндекса. Следовательно,
список ограничивает локальные вызовы HA, а не действия штатной Алисы в целом.

## Сборка

Нужен Go **1.27.3**. Windows PowerShell:

```powershell
.\scripts\build-local-ha.ps1
# Либо путь к portable Go:
.\scripts\build-local-ha.ps1 -GoExe C:\path\to\go.exe
```

Скрипт проверяет обработчик, весь пакет маршрутизации и релевантные тесты
конфигурации, затем создаёт `dist/quasar-bridge-local-arm64`. Исходные Unix-вызовы
Setsid вынесены в платформенный файл; Linux-поведение сохранено. Полный набор
командных тестов upstream не переносим на Windows из-за Unix-прав и хранилища
ChatGPT. На Linux можно выполнить весь набор:

```sh
GOEXPERIMENT=jsonv2 CGO_ENABLED=0 go test ./internal/directha ./internal/bridge ./cmd/quasar-bridge
GOEXPERIMENT=jsonv2 CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -buildvcs=false -ldflags '-s -w' -o dist/quasar-bridge-local-arm64 ./cmd/quasar-bridge
```

Тесты проверяют точное совпадение, отрицания/лишние слова, дубли фраз,
ограничение адреса HA, сервис и entity_id, отсутствие редиректов/повторов,
read-only проверку API и звуковое подтверждение без TtsGenerate.

## Установка на колонку

1. Сначала установите стандартный Bridge v0.7.6 по upstream-инструкции.
2. Сохраните исходные `app/bin/quasar-bridge`, `config.json`, `runtime.env`
   (если существует) и конфигурацию голосового сервиса. Не публикуйте бэкапы.
3. Скопируйте бинарник в отдельный временный файл на колонке и сверьте SHA256.
4. Скопируйте пример в `config.local.json`, задайте адрес HA и свои entity_id.
5. Сохраните долгосрочный HA-токен только на колонке в `runtime.env`:

   ```sh
   QUASAR_HA_TOKEN="ВАШ_ТОКЕН"
   ```

   Права файла — `0600`. Не добавляйте этот файл в Git.
6. После загрузки переменных окружения выполните новым бинарником
   `-config config.local.json -check-config` и `-check-backends`.
   Вторая команда читает только `/api/`, не переключая устройства.
7. Проверьте `-route 'включи свет'` → `home/direct_ha`,
   `-route 'включи музыку'` → `yandex/local_allowlist_miss`.
   `-route` безопасен для проверки; `-query` выполняет выбранное действие.
8. Остановите Bridge, замените бинарник и активный конфиг, запустите сервис.
   При запуске из короткой SSH-сессии используйте `setsid`, иначе дочерний
   процесс может завершиться при разрыве соединения.
9. Если endpoint ещё не переключён, выполните штатный `control.sh apply`
   и перезагрузите колонку. Для обновления уже подключённого Bridge достаточно
   перезапуска сервиса. Проверьте команды и музыку голосом.

Правила `direct_ha` применяются после полного перезапуска. Не заменяйте этот
бинарник upstream-обновлением без повторного переноса изменений: upstream
не знает режима `local`. Для отката верните сохранённые бинарник и конфиг;
штатный `control.sh rollback` восстанавливает endpoint Яндекса.

Остальные возможности upstream и его лицензии сохранены.
